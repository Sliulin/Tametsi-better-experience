# Tametsi Mod v4：P 键常驻高亮与菜单旗标修复

## 开始使用

本目录已经放好编译后的 Mod，可以直接使用，无需安装 Java、Go 或额外 Mod 框架。

1. 更新时正常退出 Tametsi 和旧 Mod 启动器，将 v4 包中的 `Tametsi Mod Manager.exe` 与整个 `mods` 文件夹放到 `tametsi.exe` 所在目录。`Tametsi Mod.cmd` 是备用入口，也可一起复制。
2. 双击 `Tametsi Mod Manager.exe` 打开 Mod 管理器。
3. 勾选“启用 Mod”，选择各项功能，再点击“确定并保存”。仅勾选而不确定，不会写入设置。
4. 以后直接打开原版 `tametsi.exe` 即可读取保存的 Mod 状态；也可用管理器的“启动游戏”。在原版启动窗口点击 `Play`。
5. 游戏运行期间修改并保存设置，下次启动才生效。关闭 Mod 同样需要在管理器中取消勾选并确定，然后正常重启游戏。

管理器可以分别开关七项功能：数字格展开、数字格自动插旗、Ctrl 高亮过滤、行列提示展开、每次启动自动备份、中央旗标、P 键常驻邻居高亮。主开关关闭时所有功能停止；各项选择仍会保留，供下次启用。

exe 直接运行图形管理界面，没有 cmd 黑窗口。它使用原版 `jre` 文件夹中的 Java 和 Windows .NET Framework 4；当前电脑已具备此环境。exe 与 cmd 读取同一份设置，更新时按 `mods/active-runtime.txt` 加载当前版本，管理器 exe 无需随每次 jar 更新重编译。exe 需要与 `mods` 一起安装，不能单独复制到其他目录使用。

重新编译 exe 可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File mods/build-manager-exe.ps1`；源码为 `mods/launcher-src/ManagerLauncher.cs`，使用 Windows 自带的 .NET Framework C# 编译器，不下载构建依赖。`mods/test-manager-exe.ps1` 会在隔离副本中启动实际 exe，验证管理界面、开关和版本加载，不显示测试窗口。

## 操作功能

数字格与行列提示使用原版“揭开”的鼠标按钮，默认左键。

当周围插旗数量**严格等于数字格的雷数**时，展开相邻未揭开、未插旗的格子。插旗不够或过多时，不展开。插错旗仍可能揭开真正的雷，进入原版失败状态。

当**相邻未揭开且未插旗的格子数 = 原始数字 − 相邻已有旗数**时，同样点击该数字格，会将这些剩余格全部插旗。例如数字为 4，原本有 5 个空白邻居，揭开一个后剩下 4 个，点击数字格即可给这 4 格插旗；已有 1 面旗且剩下 3 格时，只新增 3 面旗。重复点击不会重复计数。此判断只使用数字、旗子和揭开状态。

按住原版 Ctrl 邻居显示键并悬停在数字格上时，高亮**未揭开的邻居，包括已插旗的格子**；已揭开的相邻数字格和零格不再高亮。格子本身仍正常显示，只是不加入邻居高亮。重绑“显示邻居”按键后，也使用同样的过滤规则。

**P 键常驻邻居高亮**：在管理器中启用该功能并保存后，游戏内按一次 P 开启，再按一次关闭。开启时把鼠标移到格子上，即可显示原版邻居高亮，不需要按住 Ctrl。长按 P 不会反复切换；Ctrl 仍可正常使用，松开 Ctrl 不会关闭 P 开启的高亮。“Ctrl 高亮过滤”选项也适用于 P；关闭过滤选项后，P 会显示原版的全部邻居。

P 的开启状态只保留在当前游戏会话中，切换关卡后仍保留，重新启动游戏默认关闭。在菜单、加载、胜负状态、绘图或显示画布时，常驻高亮暂停，P 不切换状态。该功能只修改显示，不揭开、插旗、自动解题或写入存档。启用该功能时，游戏内的普通 P 键用于此切换。

**行列总雷数提示展开**：相应行、列或斜线中已有旗数等于提示的总雷数时，点击棋盘边缘的提示数字，展开该提示集合中未揭开、未插旗的格子。使用原版的成员编号集合，支持非方格和旋转提示。旗子未齐时仍保留原版的提示线切换行为。零雷提示也可以展开；标错旗仍可能踩雷，不检查隐藏雷值来代替玩家判断。

**中央旗标**：在已插旗格中央叠加彩色 🚩，保留原版底色和轮廓。图标大小随格子的实际多边形尺寸缩放，窄格会自动缩小并裁剪到格内。取消插旗后图标消失。

v4 修复关卡选择页误显示旗标：原版用标记状态表示未解锁的关卡格，现在只在正式关卡和附加关卡中叠加旗标，关卡与存档选择页保持原样。未解锁状态和关卡进度不受影响。

这个功能只响应鼠标揭开操作。左右键互换后，跟随原版鼠标揭开绑定；键盘揭开行为保持原版逻辑。菜单、绘图、暂时显示画布、加载中和胜负状态不会触发展开；隐藏数字格也不会用于推断。

## 特殊棋盘

按游戏的 `Node.getNeighbors()` 获取邻居，按 `Graph.pointInNode()` 判断点击位置。

没有使用方格八方向算法，也没有假定格子的宽高、形状或邻居数量。六边形、十边形、不同大小和不规则排列都使用游戏自身的几何与邻接关系。揭开后的空白区域展开也由原版引擎完成。

## Mod 管理与原版 exe

- 初始开关为关闭；开关保存在 `mods/settings.properties`。
- 管理器中点击“确定并保存”后，原版 exe 每次启动读取本次设置。改动不会影响已经运行的游戏。
- 管理器在根目录自动生成或更新 `tametsi.l4j.ini`，通过原版 Launch4j 参数机制加载独立组件，保留其他已有参数。首次修改前保存原参数文件到 `mods/installation/tametsi.l4j.ini.original`。
- 主开关关闭时，启动接入组件只负责会话锁和启动记录，不安装输入处理器、不变更原版绘制、不自动备份。游戏操作与高亮恢复原样。
- 关闭管理器不会强制关闭已经启动的游戏。
- 检查游戏进程，并用文件锁阻止多个会话写同一存档。备份和恢复也会检查游戏是否已经退出。
- Mod 接入失败或游戏版本不匹配时会报告原因，不显示为启用成功。可以在管理器中关闭 Mod 后再次启动。

原始 `tametsi.exe` 保持完整。独立 Mod 没有覆盖或修改原版程序。

新版运行文件单独存放在 `mods/versions/`，`mods/active-runtime.txt` 指向当前管理器版本。更新不会覆盖旧 jar；更新后重新打开管理器并确定设置，才会将原版 exe 接入新版。旧版本与日志不会被自动删除。

## 存档与备份

共用原版的三个存档槽：`profiles/p0.sav`、`profiles/p1.sav`、`profiles/p2.sav`。操作和进度通过原版接口记录，存档格式保持原样。Mod 设置另存。

**关闭 Mod 不会回退进度。** 正常退出后，原版能继续读取开启 Mod 期间保存的进度。

启用“每次启动自动备份”后，每次打开原版 exe，均会在进入原版启动窗口前备份已有的三个存档和 `config.txt`。备份完成并校验成功，游戏才会继续启动。打开管理器或仅保存设置不会创建游戏启动备份。

自动备份目录为 `mods/backups/automatic/`，最多保留最近 **10 个**，使用 `startup-01.zip` 至 `startup-10.zip` 固定槽。达到 10 个后，先生成并校验新快照，再原子替换最旧快照。整个流程不批量删除文件或目录。槽编号不是时间顺序，恢复界面会按清单时间排列。

关闭自动备份功能后，不新增快照，也不删除已有备份。v1/v2 已有备份、手动备份、恢复前备份另行保留，不受自动备份的 10 个槽轮换影响。

也可以在游戏已退出时点击“备份存档”，手动创建快照。

- 备份目录：`mods/backups/`。
- 自动快照记录北京时间；手动备份与恢复前备份使用时间和唯一标识。
- 清单记录存在的文件以及 SHA-256 校验值。尚未创建的存档槽与已有的空存档分别记录。
- 不备份或修改 `steam_autocloud.vdf` 的账户标识。
- 自动快照最多 10 个，通过替换最旧槽轮换；没有递归或批量删除操作。

## 恢复进度

1. 正常退出游戏。
2. 打开管理器，点击“恢复备份…”，选择自动 ZIP 快照或已有手动备份。
3. 查看时间和文件清单，再确认恢复。

恢复会先校验备份，然后另存当前进度与配置。当前备份失败就停止恢复。写回使用临时文件与替换流程；发生部分失败时，会报告已恢复的文件及恢复前备份位置。

恢复备份会将对应的本地进度与原版设置退回到备份时；备份时不存在的文件，会保留当前内容，不删除当前存档槽。

Steam 云同步与成就尚未做在线实测。本工具恢复的是本地文件，不代表云端已经恢复。

## 安装独立压缩包

将压缩包解压到同一版本 Tametsi 的游戏目录，使 `Tametsi Mod Manager.exe` 和原版 `tametsi.exe` 位于同一层，`mods` 文件夹也在这一层，然后按“开始使用”操作。cmd 是备用入口。

管理器 exe 另通过 22 项专项检查，涵盖含空格路径、从其他目录启动、保存的主开关和独立功能设置、新增 P 功能开关、切换活动 jar、原版启动命令，以及只打开管理器不修改设置或安装接入。

压缩包只包含 Mod、源码、脚本和许可，不包含游戏程序、运行环境、关卡或用户存档。
