# Tametsi Better Experience

为 Tametsi 提供数字格快捷操作、邻居高亮、中央旗标和存档备份，支持六边形、不同大小及不规则棋盘。所有功能均可在 Mod 管理器中独立开关。

**本 Mod 完全由 AI 编写。** 复用的第三方代码和图形资源保留各自的作者、来源与许可，见 `THIRD_PARTY.md`。

## 开始使用

本目录已经放好编译后的 Mod，可以直接使用，无需安装 Java、Go 或额外 Mod 框架。

1. 更新时正常退出 Tametsi 和旧 Mod 启动器，将 v4 包中的 `Tametsi Mod Manager.exe`、`Tametsi Mod.cmd` 与整个 `mods` 文件夹放到 `tametsi.exe` 所在目录。
2. 双击 `Tametsi Mod Manager.exe` 打开 Mod 管理器；也可使用 `Tametsi Mod.cmd` 备用入口。
3. 勾选“启用 Mod”，选择各项功能，再点击“确定并保存”。仅勾选而不确定，不会写入设置。
4. 以后直接打开原版 `tametsi.exe` 即可读取保存的 Mod 状态；也可用管理器的“启动游戏”。在原版启动窗口点击 `Play`。
5. 游戏运行期间修改并保存设置，下次启动才生效。关闭 Mod 同样需要在管理器中取消勾选并确定，然后正常重启游戏。

管理器可以分别开关七项功能：数字格展开、数字格自动插旗、Ctrl 高亮过滤、行列提示展开、每次启动自动备份、中央旗标、P 键常驻邻居高亮。主开关关闭时所有功能停止；各项选择仍会保留，供下次启用。

GitHub 仓库和发布包的顶层包含以下三项。运行文件随 `mods` 提供，无需自行编译；从 Release 下载发布包或在 GitHub 下载仓库 ZIP 后，将这三项放到受支持的游戏目录即可。游戏本体、关卡和个人数据不随包提供。

```text
Tametsi Mod Manager.exe  管理器入口
Tametsi Mod.cmd          备用入口
mods/                    Mod 运行文件、源码和说明
```

exe 与 cmd 打开相同的图形管理器、读取同一份设置，任选一种入口即可。管理器 exe 是独立启动程序，原版 `tametsi.exe` 保持完整；exe 需与 `mods` 文件夹配套使用，并使用游戏附带的 Java 环境。

## 功能介绍

| 功能 | 效果 |
| --- | --- |
| 数字格展开 | 周围插旗数等于数字时，点击数字格，一次揭开剩余未插旗的邻居。 |
| 数字格自动插旗 | 剩余空白邻居都应为雷时，点击数字格，一次标记这些格子。 |
| Ctrl 高亮过滤 | 查看邻居时跳过已揭开的格子，仅高亮未揭开格与旗子。 |
| 行列提示展开 | 对应范围的插旗数等于总雷数时，点击边缘提示，展开剩余未插旗格。 |
| 每次启动自动备份 | 游戏启动前备份存档与配置，最多保留最近 10 个自动备份。 |
| 中央旗标 | 在标记格中央显示彩色 🚩，大小随格子尺寸变化。 |
| P 键常驻邻居高亮 | 按 P 切换，鼠标悬停即可查看邻居，无需按住 Ctrl。 |

### 1. 数字格展开

当相邻插旗数**严格等于数字格的雷数**时，点击已揭开的数字格，自动揭开相邻未揭开、未插旗的格子。

例如：数字为 **3**，周围已经插了 **3 面旗**，点击该数字格即可一次展开其余空白邻居。插旗不足或过多时不会展开。

### 2. 数字格自动插旗

当**相邻未揭开且未插旗的格子数 = 数字 − 相邻已有旗数**时，点击已揭开的数字格，自动给剩余格子插旗。

例如：数字为 **4**，原本有 5 个空白邻居，揭开一个后剩下 **4 个**，点击数字格即可全部标记；如果已有 **1 面旗**、剩下 **3 个空格**，则只新增 3 面旗。

### 3. Ctrl 高亮过滤

按住 Ctrl 并将鼠标悬停在格子上时，只高亮**未揭开的邻居，包括已插旗的格子**。已揭开的相邻数字格和零格不再高亮。

如果在原版设置中更改了“显示邻居”按键，该过滤规则同样适用；也适用于 P 键开启的常驻高亮。

### 4. 行列提示展开

当某行、某列或斜线范围内的插旗数**等于边缘提示的总雷数**时，点击提示数字，自动揭开该范围内剩余未揭开、未插旗的格子。

例如：一行的总雷数为 **4**，该行已有 **4 面旗**、提示数字变灰后，点击提示即可展开剩余格子。零雷提示也可以展开；条件不满足时保留原版的提示线切换操作。

### 5. 每次启动自动备份

启用后，每次启动游戏都会在进入原版启动窗口前备份三个存档槽和 `config.txt`，最多保留最近 **10 个自动备份**。达到上限后，新备份完成并校验通过，再替换最旧备份。

仅打开管理器或保存设置不会创建启动备份。关闭该功能后，已有备份仍会保留；手动备份和恢复前备份不参与自动轮换。

### 6. 中央旗标

在已插旗格中央叠加彩色 **🚩**，保留原版底色与轮廓。图标按实际格子尺寸缩放，适应不同形状和大小；取消插旗后消失。

旗标仅在关卡内显示，关卡选择页和存档选择页不会出现额外旗标。

### 7. P 键常驻邻居高亮

游戏内**按一次 P 开启，再按一次关闭**。开启后，将鼠标移到格子上即可显示邻居，无需按住 Ctrl。

- 长按 P 不会反复切换，Ctrl 仍可正常使用。
- 开启“Ctrl 高亮过滤”时，只显示未揭开的邻居和旗子；关闭过滤时显示原版的全部邻居。
- 切换关卡保留 P 状态，重新启动游戏默认关闭。
- 在菜单、加载、胜负状态、绘图或显示画布时暂停常驻高亮，P 不切换状态。

### 操作说明

数字格展开、自动插旗和行列提示展开使用原版鼠标“揭开”按钮，默认左键；左右键互换后跟随原版绑定。键盘揭开保持原版逻辑。

这些快捷操作只在正常关卡状态下生效，不使用隐藏数字进行推断。**标错旗仍可能导致踩雷**，请先确认标记再点击展开。

## 特殊棋盘

按游戏的 `Node.getNeighbors()` 获取邻居，按 `Graph.pointInNode()` 判断点击位置。

没有使用方格八方向算法，也没有假定格子的宽高、形状或邻居数量。六边形、十边形、不同大小和不规则排列都使用游戏自身的几何与邻接关系。揭开后的空白区域展开也由原版引擎完成。

## Mod 管理与原版 exe

- 初始开关为关闭；开关保存在 `mods/settings.properties`。
- 管理器中点击“确定并保存”后，原版 exe 每次启动读取本次设置。改动不会影响已经运行的游戏。
- 管理器在根目录自动生成或更新 `tametsi.l4j.ini`，通过原版 Launch4j 参数机制加载独立组件，保留其他已有参数。首次修改前保存原参数文件到 `mods/installation/tametsi.l4j.ini.original`。
- 主开关关闭时，启动接入组件只负责会话锁和启动记录，不安装输入处理器、不变更原版绘制、不自动备份。游戏操作与高亮恢复原样。
- 关闭管理器不会强制关闭已经启动的游戏。
- 检查游戏进程，并用文件锁阻止多个会话写同一存档。备份和恢复也会检查游戏是否已经退出。
- Mod 接入失败或游戏版本不匹配时会报告原因，不显示为启用成功。可以在管理器中关闭 Mod 后再次启动。

原始 `tametsi.exe` 保持完整。独立 Mod 没有覆盖或修改原版程序。

新版运行文件单独存放在 `mods/versions/`，`mods/active-runtime.txt` 指向当前管理器版本。更新不会覆盖旧 jar；更新后重新打开管理器并确定设置，才会将原版 exe 接入新版。旧版本与日志不会被自动删除。

## 存档与备份

共用原版的三个存档槽：`profiles/p0.sav`、`profiles/p1.sav`、`profiles/p2.sav`。操作和进度通过原版接口记录，存档格式保持原样。Mod 设置另存。

**关闭 Mod 不会回退进度。** 正常退出后，原版能继续读取开启 Mod 期间保存的进度。

启用“每次启动自动备份”后，每次打开原版 exe，均会在进入原版启动窗口前备份已有的三个存档和 `config.txt`。备份完成并校验成功，游戏才会继续启动。打开管理器或仅保存设置不会创建游戏启动备份。

自动备份目录为 `mods/backups/automatic/`，最多保留最近 **10 个**，使用 `startup-01.zip` 至 `startup-10.zip` 固定槽。达到 10 个后，先生成并校验新快照，再原子替换最旧快照。整个流程不批量删除文件或目录。槽编号不是时间顺序，恢复界面会按清单时间排列。

关闭自动备份功能后，不新增快照，也不删除已有备份。v1/v2 已有备份、手动备份、恢复前备份另行保留，不受自动备份的 10 个槽轮换影响。

也可以在游戏已退出时点击“备份存档”，手动创建快照。

- 备份目录：`mods/backups/`。
- 自动快照记录北京时间；手动备份与恢复前备份使用时间和唯一标识。
- 清单记录存在的文件以及 SHA-256 校验值。尚未创建的存档槽与已有的空存档分别记录。
- 不备份或修改 `steam_autocloud.vdf` 的账户标识。
- 自动快照最多 10 个，通过替换最旧槽轮换；没有递归或批量删除操作。

## 恢复进度

1. 正常退出游戏。
2. 打开管理器，点击“恢复备份…”，选择自动 ZIP 快照或已有手动备份。
3. 查看时间和文件清单，再确认恢复。

恢复会先校验备份，然后另存当前进度与配置。当前备份失败就停止恢复。写回使用临时文件与替换流程；发生部分失败时，会报告已恢复的文件及恢复前备份位置。

恢复备份会将对应的本地进度与原版设置退回到备份时；备份时不存在的文件，会保留当前内容，不删除当前存档槽。

Steam 云同步与成就尚未做在线实测。本工具恢复的是本地文件，不代表云端已经恢复。

## 日志、构建与验证

- 每次启动的游戏日志：`mods/runs/<会话标识>/game.log`。
- 构建：在游戏目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File mods/build.ps1`。
- 测试：运行 `powershell -NoProfile -ExecutionPolicy Bypass -File mods/test.ps1`。
- 打包：运行 `powershell -NoProfile -ExecutionPolicy Bypass -File mods/release.ps1`。
- 重新编译管理器 exe：运行 `powershell -NoProfile -ExecutionPolicy Bypass -File mods/build-manager-exe.ps1`，使用 Windows 的 .NET Framework 4 C# 编译器；源码在 `mods/launcher-src/ManagerLauncher.cs`。
- 构建使用游戏附带的 Java 8，源码在 `mods/src/tametsimod/`。
- 测试使用 `mods/test-runs/` 中的隔离副本，保留产物，遵守禁止批量删除的项目规则。

## 安装独立压缩包

将压缩包解压到同一版本 Tametsi 的游戏目录，使 `Tametsi Mod Manager.exe`、`Tametsi Mod.cmd`、`mods` 文件夹和原版 `tametsi.exe` 位于同一层，然后按“开始使用”操作。

压缩包只包含 Mod、源码、脚本和许可，不包含游戏程序、运行环境、关卡或用户存档。
